## Hosted/Vendor Builtin Meaning

Hosted/vendor builtin means a compiler-recognized extension used by hosted standard-library implementations or compatibility shims, not a local helper with a reserved-looking name. The initial no-action scan found `__decay(T)`, `__remove_reference_t(T)`, `__remove_cv(T)`, `__remove_cvref(T)`, `__type_pack_element<I, T...>`, and `__make_integer_seq<...>` in eight rows. Those eight rows have now been rewritten to portable C++11 helpers, and the PA19-PA23 placement audit no longer reports `template.builtin_traits` findings.

The scan found no angle-bracket hosted STL includes among no-action rows. One row includes local `"../support.h"`, which is not a hosted header finding.

Reserved-looking local declarations such as `std::__copy_n`, `__difference_type`, `__ratio_gcd`, `__bool_constant`, and `_TCC::__is_implicitly_constructible` are not hosted/vendor intrinsic dependencies by themselves. The placement audit script filters locally declared double-underscore names for `template.builtin_traits`.

Host predefined macro/type spellings such as `__SIZE_TYPE__` are a separate PA34 compatibility category. They are not hosted headers and not local helpers; they are host predefined macro imports from the configured host toolchain. The PA19/PA23 source uses found during this pass were rewritten to portable C++11 spellings.

The PA19, PA20, PA21, PA22, and PA23 README boundaries all exclude hosted/vendor-only template traits and intrinsics. Therefore rows with actual intrinsic dependencies are wrong for earlier core-template PA placement as written when the intrinsic is essential. The ordinary template-semantics rows have been rewritten locally; intrinsic-specific behavior remains PA34 hosted compatibility and is covered by PA34 compile-only tests.
