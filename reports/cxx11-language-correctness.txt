C++ correctness campaign: revised oracle and first outcome screen
2026-11-06 | investigate/upstream-cxx11

The objective is C++ correctness. Diagnostic spelling, counts, source locations,
notes, recovery and optional warnings are not repair requirements. The existing
26/720 (3.6%) native assertion result is not a C++ correctness pass rate.

Required checks

- Valid programs: accept and produce objects; link and execute where required,
  retaining program-output, ABI and other independent behavior checks.
- Ill-formed programs requiring a diagnostic: normal compiler termination and
  a diagnostic from compilation. A diagnosed extension may still be accepted.
  Compiler crashes, timeouts, silent rejection and linker errors do not satisfy
  this obligation. Diagnostic presence on a mixed-invalid source is only a
  whole-translation-unit check: isolate each rule and add valid mirrors in the
  owning PA to establish feature coverage.
- Classify original C++11, later CWG/DR, IFNDR, deliberate extensions, unspecified
  behavior and unresolved standards questions separately. Required later-DR
  repairs stay in scope. Upstream compiler behavior is evidence, not the rule.
- Keep warning escalation, unsupported interfaces, unprojected codegen checks
  and incomplete runtime/output checks visible until reviewed and replayed.

Implementation and validation

scripts/upstream_language_outcomes.py classifies immutable native receipts using
active host metadata to discover provisional positive/negative expectations.
Candidate diagnostic regexes/counts never enter its decision. Compiler stages
are separated from host linking and capability probes. Program execution and
output obligations remain required. scripts/summarize_upstream_language_campaign.py
first uses the existing campaign verifier to rehash sources, streams, artifacts,
compiler and adapter; it then pairs identical source/dialect variants. Explicit
standards dispositions are pinned to exact source hashes in
reports/cxx11-language-dispositions.json.

Twenty meaningful boundary controls pass, covering equivalent wording and
first-error-only diagnosis, missing/silent diagnostics, diagnosed extensions,
positive rejection, optional warnings, abnormal compilation, capability probes,
warning escalation, IFNDR, runtime/output obligations, linker-only diagnostics,
combined negative compile/link ambiguity, missing compiler stages, option
blockers, preprocessing output and unprojected codegen checks. make test-harness
