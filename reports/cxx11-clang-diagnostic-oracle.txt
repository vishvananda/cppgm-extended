The helper discovers expectations through native preprocessing in a supplied
cc1 context and consumes structured diagnostic events. It performs no C++
semantic analysis. Native preprocessing diagnostics stay separate from the
supplied compiler stream; malformed expectation directives use the native
verification engine. Event source mapping requires a discovered file and
presumed line; ambiguous/unmappable locations become explicit blockers. Native
verify does not assert diagnostic columns, which remain in the event artifact.

Stored-message Diagnostic objects are replayed directly into the native
consumer. Re-emitting a supplied stream through compiler warning policy could
hide warnings under-w or upgrade them under-Werror. The old unbuilt draft is
retained and its exact waiting worker was retired before any build/control
invocation. The current v2 source and protocol add explicit fault controls for
that distinction; no measured observation was deleted or rerun.

Declared controls:21 native-verify equivalence cases, four abnormal/timeout/
silent-rejection/unmappable blockers, one preprocessing-error boundary and two

warnings, notes, inactive conditionals, included files, presumed#line locations,
