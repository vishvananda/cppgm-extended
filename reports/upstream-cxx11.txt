Confirmed high-priority findings

1. sfinae57.C reproducibly SIGSEGVs. The saved gdb backtrace begins in
   sema::NameLookup::find, through constructor_candidates, record_copy,
   convert_arguments, decltype substitution and template deduction.
   This is a robustness defect in the incomplete-class/SFINAE path.

2. alias-decl-17.C is accepted, although both GCC and Clang reject the
   unexpanded parameter pack in an alias template. abstract-default1.C is
   accepted, although both reject abstract-class default argument construction.
   These demonstrate real missing diagnostics, beyond harness flag differences.

3. Clang CodeGenCXX/cxx11-initializer-aggregate.cpp exceeds both the original
   15-second timeout and an isolated 45-second recheck in syntax-only mode.
   It contains an aggregate with 2^31 int elements. Investigate compact handling
   of zero-initialized tails; do not infer the exact cause from timeout alone.

What native suite integration requires

GCC:
- Add an explicit external lane, leaving the course default discovery intact.
- Pin source revisions and preserve upstream licenses/comments; keep sources
  outside the export and record every selected/skipped test and its reason.
- Prefer DejaGnu's own metadata evaluation; do not turn the survey's regex
  selector into a general dg parser. Honor language/target selectors,
  effective-target probes, dg-options/additional-options, extra translation
  units, expected failures, diagnostic expectations and timeout/crash states.
- Use a compiler/board adapter that compiles with cppgm and links hosted
  runtime tests with the host compiler. Force the C++11 standard list.
- GCC's compile tests commonly use -S. cppgm currently rejects -S, verified
  directly. For semantic-only coverage, map eligible compile tests to
  -fsyntax-only and mark assembly/scan-assembler tests unsupported. Object
  tests must actually use -c. Supporting real assembly output is separate work.
- cppgm accepts many -W/-f/-m options without implementing their behavior;
  capability checks must prevent those from silently becoming false passes.
- Diagnostic text differs and warnings/pedantic behavior are incomplete.
  Initially report coarse accept/reject separately; exact dg-error/warning
  compatibility is a later milestone and must never count a crash as rejection.

Clang:
- Use a separate lit configuration or an explicit RUN-line adapter for the
  portable C++11 subset. Preserve standard-specific verify prefixes and guards.
- cppgm rejects -cc1, -verify and -emit-llvm. Native Clang RUN lines therefore
  cannot be redirected wholesale to cppgm.
- Translate eligible syntax invocations to the driver; implement diagnostic
  checking using structured severity/location/category where possible. Existing
  GCC/Clang wording checks require either mapped expectations or compatible
  diagnostics, explicitly reported as adapted coverage.
- AST-dump checks and FileCheck tests of LLVM IR do not describe cppgm's
  outputs. Skip them explicitly in native-form conformance coverage; use
  execution/ABI/object checks for equivalent backend behavior. The survey's
  syntax acceptance of a CodeGenCXX source does not validate its codegen checks.
- Respect REQUIRES/UNSUPPORTED/XFAIL, target triples, split-file inputs,
  substitutions, includes, compiler-specific builtins and multiple RUN lines.

Next implementation order

1. Check in an external lane with pinned fetch manifests and explicit eligibility
   rules. Retain per-case commands/stdout/stderr and separate skip, reject,
   crash, timeout, codegen, link and execution outcomes.
2. Fix the SFINAE crash, two confirmed false accepts and three runtime aborts.
   Reduce cases into the earliest owning PA feature lane before compiler fixes.
3. Expand valid C++11 compile/object/run coverage by feature, separating GNU
   extensions, platform cases and mixed negative files. Then implement reliable
   negative diagnostics and expand to library suites as a distinct project.
4. Every compiler fix must follow spec.md, relevant handouts, full strict report,
   debug-info/self-host checks and architecture audits. Backend/lowering changes
   additionally need PA35 checks; measure compile-time or allocation effects.
