C++11 correctness CI bring-up -- 2026-11-07

.github/workflows/upstream-cxx11.yml creates two independent GCC/Clang jobs
on pull requests, main pushes and manual dispatch. Their manifest/run/report
commands have been exercised locally; no GitHub-hosted execution is claimed.
The jobs pin upstream sources and compiler package versions, build cppgm,
then select tests without invoking either compiler. Both execute the same
declared configurations with two workers: cppgm first, matching upstream next.

Fresh per-case working/output/temp directories isolate compilation and runtime.
Diagnostic spelling, count, location and recovery are not correctness checks.
A normal diagnostic satisfies a required-diagnostic case; internal errors,
signals, timeouts and link errors cannot. Positive cases require an object and
their declared link/execution checks. Unknown obligations remain exclusions.

The suite elapsed times include compilation, required linking/execution and
checking; download, build and metadata preparation precede timing. OS caches
stay enabled. Ordering, load, commands, child user/system CPU times, source
hashes, binaries and runner identities are recorded. Clang uses its native cc1
interface versus cppgm's driver: the ratio describes these declared suite
interfaces, not a pure frontend microbenchmark.

Each summary prints counts, both elapsed times and cppgm_elapsed/upstream_elapsed.
Failures, incomplete work or changed inputs/tools make the ratio non-comparable
and fail the job. The second compiler still runs after ordinary compiler or
harness failure. Always-run summary/artifact steps retain the manifest, visible
exclusions, environment, actual commands, raw streams and JSON/Markdown results.
No upstream speed-ratio acceptance threshold or new calibration is introduced.
