Reliable scheduling and resume

The scheduler assigns the actual native driver before selecting a case.
Specialized .exp families, unsupported input kinds, missing selected identities
and Clang inputs have explicit per-file dispositions. It does not silently
route Old-Deja/torture/module cases through the ordinary dg driver. The single
adapter still executes original native Tcl metadata and records its adaptations.

The compiler and all adapter scripts are copied before execution. The manifest
binds the inventory, selected-observation snapshot, source hashes, driver and
native helper files, compiler/tool hashes, environment, dialects, modes and
resource limits. The native DejaGnu fingerprint now includes configuration and
board helper subdirectories. A native framework ERROR/WARNING takes precedence
over an accompanying FAIL assertion, avoiding a false compiler-defect label.

A kernel file lock prevents concurrent schedulers. Each cell has its own
persistent state and artifacts. Resume verifies terminal result/config/manifest
hashes, waits for any exact surviving PID/start-time identity, and records a
missing result from a terminated worker as harness-incomplete. It never silently
restarts such a cell or overwrites its evidence. SIGINT/SIGTERM stop scheduling
new cells and drain the bounded active worker set; interruption does not mean
that the campaign is complete. Native-adapter signal handlers unwind process
cleanup rather than abandoning a compiler/runtime process group.

Both completed campaigns were resumed using their frozen adapters. All 6480
checked state, worker-output and native-result files retained identical bytes
and modification times: no compiler case was reexecuted. resume-checks.json
retains exact commands, return codes and timings. The 41 boundary/native
integration regressions pass, including live-worker attachment, PID reuse,
source/result drift, unavailable drivers, duplicate identities and overlapping
scheduler rejection. Full make test-harness passes: 34 suites, 516 discovered
tests, with external-native integration separately enabled for all 41 controls.

Additional standards triage

CXX11-019 maps four original observations (constexpr-mutable1/2/4/6.C) to later
CWG 1405 compatibility. N3485 5.19p2 permits the relevant constexpr-object
subobject reads without a non-mutable qualification. CWG 1405's proposal was
written in February 2012 but moved to DR at the April 2013 meeting; its added
non-mutable restriction is absent from the release draft. The original source
files and valid nonmutable neighbors match all declared outcomes in a separate
30-cell GCC/Clang/candidate ISO/GNU11 control matrix. The issue's primary source,
retrieved bytes, hashes and commands are retained under issues/CXX11-019.
constexpr-mutable3.C involves a by-value parameter and remains separate pending
analysis; it is not grouped merely because its filename contains mutable.

The issue ledger now has 19 issues and 548 observations. All original observations

No compiler source, binary or reference changed in this checkpoint. The latest
