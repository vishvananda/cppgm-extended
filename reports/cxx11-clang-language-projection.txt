Clang C++11 language-projection checkpoint
2026-11-06 | investigate/clang-cxx11-correctness

This adapter checks projected C++ language/object obligations. Candidate
diagnostic words, counts, locations, notes, optional warnings and recovery do
not enter the score. It is not a complete native lit adapter or a Clang corpus
correctness percentage. Every original RUN and every remaining interface,
configuration, runtime and standards question stays visible.

Implementation

scripts/upstream_clang_expectations.cpp uses LLVM21.1.8's public preprocessor
and VerifyDiagnosticConsumer APIs to discover active required-error comments.
It parses no C++ AST and receives no candidate diagnostic events. Native
verification against an empty stream identifies required expectation severity
through typed native diagnostic IDs/arguments; no candidate regex matching is
performed. Native preprocessing and malformed expectation failures block.

The same helper compares native preprocessed tokens with cppgm's documented
PA4 stream, decoding source spellings with Clang's raw lexer. Differing compiler
macros/branches cannot silently create a language failure or pass. Literal
values remain outside this context-equivalence check. Source pragmas retain
their native physical provenance and require reviewed policy equivalence.
The two exact push_macro directives from Clang's nonphysical predefines are
recorded as infrastructure; a physical source pretending to be <built-in>
does not receive that exemption.

scripts/upstream_clang_language.py explicitly maps reviewed cc1 arguments.
Unknown semantic options, warning escalation, unsupported targets/dialects,
explicit exception/RTTI-disable configurations and unprobed features block.
Native typed throw/try/catch tokens under cc1's default disabled-exception
policy also block: cppgm's driver accepts these modes without enforcing the
same language restrictions. Strings/comments do not trigger the token guard.
This is an explicit configuration limitation, not a C++ language defect.

scripts/run_upstream_clang_language.py uses pinned native lit parsing, ordered
file substitutions, native feature expressions and native shell structure.
It predeclares every selected RUN/dialect task and accounts for the complete
20,491-file metadata inventory. No local configuration is silently ignored:
those require evaluation. The original153-file cohort has no local configs.
Only a declared, limited Linux x86-64 language projection configuration is
loaded; the complete upstream CMake-generated site configuration is unfinished.

Positive syntax projections generate host and candidate relocatable objects;
ELF headers/sections must be complete and target x86-64. FileCheck pipelines
can yield an object obligation while retaining their original output oracle
as unprojected coverage. Setup, other pipelines and runtime commands without a
reviewed mapping remain blocked. Every receipt states full_upstream_pass=false.
Negative diagnostic observations count as a required-language match/mismatch
only after a source-pinned standards adjudication. Other negatives stay under
review. A crash, timeout, internal failure or silent rejection never satisfies
a required diagnostic. No compiler source is changed by this adapter commit.
