LLVM optimization extension audit, 2026-11-09
============================================

Three gaps are fixed and fully qualified: repeatable GNU pure/const calls,
fixed-width bit reversal and non-null pointer return promises. Remaining gaps
include allocator return-alias promises, restrict, alignment, minsize and
visibility. The complete LLVM runtime speed ratio is 0.8331x native; retired
instructions are essentially unchanged, so this group does not explain the
larger code-generation gap or achieve the 0.95x objective.

Scope and evidence
------------------
Audited the exact 2577 C++ translation units feeding the LLVM 22.1.2
clang-22 target, plus their 5696 source/generated-header dependency closure.
The native and cppgm builds use identical source hashes and generated header
contents. Dependency discovery uses the native build: the cppgm object
dependency entries are empty and cannot establish header coverage.

Evidence is retained outside the checkout under
/mnt/vizier/cppgm-llvm-evidence/llvm-extension-audit:
clang-target-complete-inventory.json, source-feature-queries.json,
attributes-final.lowir, repeated-effects-results.json and the disassemblies.
The inventory counts lexical occurrences, including inactive code, comments
and strings; it is not a count of active annotated declarations. We separately
compared the 56 source-spelled feature queries and expanded Compiler.h macros
with the actual LLVM compilation configuration.

Findings at the accepted B26 checkpoint
--------------------------------------
* always_inline (142 LLVM macro occurrences) and noinline (54) are retained
  and consumed. Template instantiations consult their primary/pattern inline
  attributes. LLVM_LIKELY/UNLIKELY reach branch probability metadata.
* LLVM_READONLY (589) and LLVM_READNONE (14) become read-only/read-none memory
  effects. The baseline does not reuse repeated calls: a reduced pure/const
  example emits two calls with cppgm versus one with GCC 15 and Clang 22.
  Memory effects alone are insufficient to authorize reuse: read-only LowIR
  calls can perform IO. A separate repeatability fact is needed for the GNU
  pure/const promise, with memory writes and opaque/non-memory barriers handled.
* LLVM_ATTRIBUTE_RETURNS_NONNULL (65) is disabled by our feature query.
  LLVM_ATTRIBUTE_RETURNS_NOALIAS (6) expands to GNU malloc, which the parser
  accepts without retaining its return-alias promise. These lose useful
  pointer facts. A malloc attribute does not imply no global memory writes;
  it must not be treated as an existing builtin allocator's memory effects.
* __restrict/__restrict__ are discarded lexically; LLVM_ATTRIBUTE_RESTRICT
  occurs four times, including the GlobalISel decoder. No parameter no-alias
  fact reaches the optimizer.
* LLVM_ASSUME_ALIGNED (10) is advertised, but lowering currently returns the
  pointer and discards the alignment/offset promise. Its uses are in Endian.h;
  scalar unaligned x86 accesses may already have the same instruction cost.
* LLVM_ATTRIBUTE_MINSIZE (5) and visibility macros (15 combined) select
  fallbacks because our feature queries answer false. Size optimization and
  symbol visibility need distinct implementation/measurement; accepting their
  spelling alone would not implement the requested behavior.
* __builtin_bitreverse8/16/32/64 queries answer false. MathExtras.h therefore
  selects byte-table reversal with copies and a loop. This is an actual
  algorithm fallback worth reducing and measuring.
* LLVM_PREFETCH has two lexical occurrences, both in its macro definition;
  no actual LLVM source use was found in this closure. Dropping that hint is
  not evidence of a slowdown in this workload.
* Other query differences include diagnostic/debug/sanitizer annotations,
  platform-specific calling conventions and fallthrough annotations. Their
  lexical presence is not evidence that they affect this X86 Release build.
  In particular, the cold/hot/flatten spellings found by this scan are in
  generated Clang attribute tables/documentation, not active GNU annotations
  on the compiler functions being built.

Completed changes and qualification
------------------------------------
GNU repeatable scalar calls (3dd0515ee), fixed-width bit reversal (2c26e2566)
and non-null return promises (399e1c762) have passed together:
* strict 9949/9949, debug/modern, all architecture/file/placement/CWG audits,
  harness, PA5 self-host and inception;
* student export, all 42 reference-wrapper checks, all 13 new exported
  fixtures, PA35 quick/smoke and the official course/student releases 17/17;
* frozen compile instructions 0.9998385x O0 and 1.0019531x O3 (+0.1953%), with
  RSS below the parent in both cases;
* all 2577 LLVM C++ units, without fallback, in a fresh 3163-step build taking
  355.87 seconds; all 204 generated dependencies in the audited closure match
  the native build;
* all 323 current cppgm objects and linked compiler byte-identical between
  native-built and cppgm-built Clang; separately, all 323 frozen objects and
  the linked compiler match, including every timing observation.

Fixtures cover stores, volatile/opaque calls, by-value object arguments,
pointer-call and specialization controls, signed/narrow argument conversion,
all four bit widths, constant evaluation, and single operand evaluation.
GCC/Clang runtime oracles pass; bit-reversal spellings are checked against
Clang because GCC 15 does not provide them. The non-null reduction removes
three comparisons while preserving calls and the unannotated controls.
Explicit specialization attribute ownership follows GCC 15; Clang 22
inherits returns_nonnull here. Shared runtime fixtures are valid under both
interpretations, and this difference is retained in the oracle evidence.

Five existing references were regenerated through normal reference commands
to record repeatable=yes; changes are only boundary facts. The initial full
release missed course timing headroom (2.44x versus the 2.40x margin target;
hard limit 3.00x). The unchanged-build cached rerun passes: course 2.10x,
student 1.78x. Both failed and passed observations are retained.

Full runtime comparison and next work
-------------------------------------
The frozen 323-unit ABBA comparison gives native 44.715 s versus cppgm-built
53.675 s: speed ratio 0.8330694x. CPU ratio is 0.8354309x. A/A observations,
all outputs and user-mode counters are retained; counter coverage is 100%.
Cppgm-built Clang retires 1.238604 trillion instructions versus 1.238735
trillion at B26 (0.99989384x); native instructions remain stable. This is no
resolved instruction-count improvement, despite useful local reductions.

Four-unit private relinks took 8-24 seconds and also showed no resolved
downstream win. They are quick localization experiments, not full scores.
Fresh instruction/LBR profiles are in block27-runtime-profile. Forcing an
aggregate getter inline in a one-object private link did not improve its
sample; native Clang also leaves that getter outlined. Do not promote that
header override or mistake symbol-attribution movement for saved work.

The acceptance receipt is block27-attributes-qualification-state.json in the
evidence directory. Continue with measured hot-path reductions, batching
three or four supported improvements for each full rebuild. Investigate the
remaining extension promises where active hot code uses them; accepting or
advertising a spelling alone does not implement its optimization semantics.
