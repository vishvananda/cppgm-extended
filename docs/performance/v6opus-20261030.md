# v6opus performance comparison, 2026-10-30

Two small changes survived measurement: an empty-scope lookup hint and folding
masked narrow loads into memory TEST instructions. General backward bit demand
and larger O3 inlining limits did not improve the reference implementation.

The reference baseline is `bf9996a697cac60ebe1a5d4717d301ad537adef2`;
v6opus is pinned at `c066065e2f114fb2f41d0c257846771a885a8fff`. The active
v6opus checkout was left untouched. Both seeds used GCC 15.2.0 and
`-std=gnu++11 -Wall -O3 -fno-strict-aliasing`, with identical standard-library
flags. Each seed built its own compiler at O3. The frozen PA35 workload and
header manifest were identical across implementations.

## What was measured

A seed is the GCC-built compiler; a self binary is built by that seed. O0/O3
below are the optimization levels used when these binaries compile the frozen
input, not the host compiler's optimization level. Compile-only measurements
exclude linking. They measure one fixed workload rather than the time to build
the entire compiler.

The input manifest SHA256 is
`2b1edfeb32a8658c2fc607c6a251da8840af349e0fd9e54aa45f8355013959b6`;
the host-header closure SHA256 is
`39b8f94e3bd4802ce3d974795ee74bd476c56e1e023a88eb114820a24bcf3fb3`.
The machine is an Intel Xeon E5-2696 v4. Immutable A/B compiler copies, A/A
calibration, alternating ABBA/BAAB blocks, pinned cores and user-mode hardware
instruction counters were used. The combined retained comparison has six paired
blocks and two A/A blocks per level. RSS uses a separate page-table observer
rather than relying on the host's approximate wait4 peak. Every observation,
command, hash, profiler trace and unsuccessful prototype is retained in the
local campaign evidence directory `validation/20261030-v6opus-perf` in the Boost
workspace. These artifacts are not student files.

Wall-time and cycle observations were noisy during other validation work. The
small changes below are instruction-count improvements; they do not establish
sub-percent elapsed-time improvements. All compared frozen outputs are
reproducible within each binary. Constant-source codegen comparisons and each
implementation's seed/self pair also produce byte-identical objects.

## Frontend and generated-code differences

On the frozen workload, the v6opus GCC seed executes 1.700x the reference seed's
instructions at O0 and 1.794x at O3, with peak RSS ratios of 1.732x and 1.818x.
These cross-implementation results combine different algorithms and data
structures, so they cannot identify generated-code quality on their own.

Exact Callgrind attribution separates each compiler's own instructions from
library code. Comparing each self binary with its own GCC seed gives:

| Implementation | Own instructions, O0 | Own instructions, O3 | Total instructions, O0 | Total instructions, O3 |
| --- | ---: | ---: | ---: | ---: |
| Reference self / reference seed | 0.973493 | 1.000820 | 0.973167 | 1.004232 |
| v6opus self / v6opus seed | 1.077792 | 1.101138 | 1.079003 | 1.073665 |

These exact attribution runs and the separate hardware-counter runs are
reported separately; they have different measurement boundaries. Each row
compiles identical source with identical semantics and verifies object parity.

The v6opus O0 self binary makes 1.705 million more out-of-line calls to
`SemanticLookup::collect` and about one million more to
`PPLexer::starts_identifier`. At O3 it also makes 2.785 million more calls to
`std::vector<unsigned>::_M_fill_assign`. The dynamic O3 mix adds about 520 million
loads and 237 million stores. This points to inlining and generated instruction
selection as meaningful costs, in addition to the frontend's larger underlying
workload. A function absent from a call profile may have been inlined; its zero
out-of-line count does not mean the semantic work disappeared.

Single reference phase samples put frontend work at roughly 0.87–0.88 seconds.
Lowering, optimization and object generation take roughly 0.31 seconds at O0
and 1.76 seconds at O3; selection accounts for approximately 0.10/0.24 seconds
and encoding for about 0.02 seconds. These are diagnostic samples, not paired
performance claims. O0 profiles concentrate in semantic lookup, type interning
and lexing; O3 adds substantial memory forwarding and CFG/value optimization.
Linking cannot explain these compile-only results.

## Candidate decisions

Several v6opus optimizations already have reference equivalents: branch
relaxation, flag-safe XOR zeroing, constant-store merging, loop-sensitive
inlining, frame omission, shrink wrapping, register allocation/block placement,
ordinary AND-to-TEST/BT branches, canonical extension aliases and local Boolean
bit demand. Different policy constants are not automatically improvements.

| Candidate | GCC-seed instruction change O0 / O3 | Generated compiler on unchanged reference source, O0 / O3 | Decision |
| --- | ---: | ---: | --- |
| General backward integer bit demand | +0.004% / +0.258% | -0.024% / -0.018% | Reject |
| O3 hinted/call-free inline cap 96 | -0.002% / +2.251% | +1.907% / +1.031% | Reject |
| Empty-scope lookup bit | -0.238% / -0.097% | Self with source change: -0.050% / -0.019% | Retain |
| Memory TEST including promoted byte/halfword loads | +0.002% / +0.003% | -0.100% / -0.203% | Retain |

The bit-demand prototype used a widening worklist over typed LowIR, preserved
memory widths and conservatively handled calls and Boolean values. It saved
only 24 text bytes on the frozen O3 object and 736 bytes on the unchanged-source
compiler. Existing reference aliases and local cleanups cover most of the
opportunities. End-to-end self instructions increased 0.217% at O3.

Raising the inline cap grew the unchanged-source compiler's text by 4.505%.
Exact attribution found 4.678 million additional out-of-line calls to
`PPLexer::take_identifier_continue`. The evidence shows an interaction with the
existing growth/budget policy; simply accepting larger callees does not ensure
that the hottest helpers remain inline.

The retained lookup implementation stores one monotonic bit in existing Scope
padding; Scope remains 96 bytes. It records actual name-index insertions,
including hidden bindings absent from the dump-oriented binding list. An
initial separate byte-vector implementation was rejected because its own
access costs outweighed the saved table probes.

The retained native change uses the original load width for a single-use,
nonvolatile load tested through a constant mask. It proves that the mask ignores
promoted bits, bounds the intervening scan, and disallows intervening writes or
calls. The required PA33 fixture covers byte/halfword masks, signed promotions,
wide masks, volatile accesses and intervening effects. Its instruction budgets
fail on the baseline while behavior passes on both compilers. Exact attribution
of an unchanged-source compiler independently confirms own-code instruction
ratios of 0.999053 at O0 and 0.997895 at O3, with unchanged call counts.
