# Hosted Header Compatibility Tracker

Legacy note:

- Active hosted frontier work now uses:
  - `HOSTED_HEADER_FRONTIER_PROCESS.md`
  - `HOSTED_HEADER_FRONTIER_TRACKER.md`
- This file remains as historical context and back-reference material.

This is a working log for compatibility fixes discovered while pushing toward hosted-header
support and eventual bootstrap work.

The point of this file is:

- record each fix as it is made
- keep a minimal failing-test idea next to it
- decide which milestone should own the regression
- record the finalized assignment-local regression as soon as it exists

Some fixes are true PA31 hosted-compatibility work. Others expose gaps in earlier
milestones and should become earlier assignment-local regressions instead of being hidden
behind a later hosted smoke test.

## Status

- `implemented`: landed in the current tree
- `in-progress`: code is in flight but not yet fully verified
- `open`: blocker found, no fix yet

## Frontier Process

The draft-regression staging area is gone. Frontier work now uses this process:

1. When a new blocker is found, add or update the tracker row immediately.
2. Reduce it enough to identify the earliest owning assignment, but do not create a long-lived
   holding area of draft tests.
3. Fix the implementation in `dev/`.
4. Add the regression directly to the owning `paN` suite as part of the same work.
5. Run `make test` in that `paN` before moving on.
6. Update `HHC_REGRESSION_LEDGER.md` with the final numbered test path.
7. If the reduction is still too unstable or spans multiple ownership questions, keep only the
   tracker note and any minimal scratch repro outside the repo until the boundary is clear.

Practical rule:

- use `/tmp` or another scratch location for transient reductions while investigating
- once the ownership is clear and the fix is real, add the finalized regression directly to
  the owning `paN`
- do not recreate `draft_regressions/`

The default expectation is: each implemented fix leaves behind its assignment-local regression
before frontier work continues.

For implemented rows, the `Owning PA` column should reflect the current assignment owner under
the active numbering. The exact finalized test path lives in `HHC_REGRESSION_LEDGER.md`.

## Notes

- Standard-language fixes should get assignment-local regressions in the earliest milestone
  that owns them. Do not leave them covered only by a later hosted-header smoke.
- Hosted-header/vendor-extension fixes should generally be recorded against `PA31` unless we
  later decide to document them as compatibility extensions for an earlier milestone.
- When a new blocker is found, add it here before or while fixing it so we do not lose the
  test idea or the intended milestone ownership, then finalize the regression directly in the
  owning `paN` suite instead of parking it in a draft directory.
