2879. Undesired outcomes with const_cast
Section: 7.6.1.11 [expr.const.cast [1]] Status: CD7 Submitter: Brian Bi Date: 2024-04-15

[Accepted as a DR at the November, 2024 meeting.]

(From submissions #526 [2], #232 [3], and #342 [4].)

The resolution of issue 891 [5] intended to make const_cast<int&&>(2) ill-formed.
However, combined with the temporary materialization conversion turning prvalues into
glvalues (7.1 [expr.pre [6]] paragraph 7, this is now well-formed.

Also, the current rules regrettably allow const_cast<int>(0) and const_casts involving
function pointers and pointers to member functions. The latter is non-normatively
considered disallowed by the note in 7.6.1.11 [expr.const.cast [7]] paragraph 9.

Major implementations except MSVC agree with the proposed direction of this issue.

[DELETE: For two similar types T1 and T2 (7.3.6 [conv.qual [9]]), a prvalue of type T1

a null pointer or null member pointer, the result is a null pointer or null member
pointer, respectively. Otherwise, the result points to or past the end of the same
object or member, respectively, as v. ]

[DELETE:  For two object types T1 and T2, if a pointer to T1 can be explicitly converted

be made:]

[DELETE:

[DELETE: The result of a reference const_cast refers to the original object if the
operand is a glvalue and to the result of applying the temporary materialization
conversion (7.3.5 [conv.rval [11]]) otherwise. ]

[INSERT:  Otherwise, T shall be a reference type. Let T1 be the type of v and T2 be the
type referred to by T. A const_cast from "pointer to T1" to "pointer to T2" shall be
valid. If T is an lvalue reference type, v shall be an lvalue. Otherwise, if T2 is a
class type and v is a prvalue, the temporary materialization conversion (7.3.5
[conv.rval [11]]) is applied. Otherwise, the temporary materialization conversion is not
applied and v shall be a glvalue. The result refers to the same object as the (possibly
converted) operand. ]

[14]]) is converted to the null member pointer value of the destination type. ]
