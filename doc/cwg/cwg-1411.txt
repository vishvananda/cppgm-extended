1411. More on global scope :: in nested-name-specifier
Section: Clause 11 [class [1]] Status: CD3 Submitter: David Blaikie Date: 2011-10-28

[Moved to DR at the April, 2013 meeting.]

The resolution of issue 355 [2] failed to update the grammar for class-head-name in
Clause 11 [class [3]] paragraph 1 and removed the optional :: from class-or-decltype in
11.7 [class.derived [4]] paragraph 1, with the result that it is still not possible to
globally-qualify a class name in a class definition, and the ability to globally-qualify
a base class name has been lost.

Proposed resolution (February, 2012):

Change the grammar in _N4567_.5.1.1 [expr.prim.general [5]] paragraph 8 as follows:

qualified-id:

nested-name-specifier templateopt unqualified-id
[DELETE: :: identifier
:: operator-function-id
:: literal-operator-id
:: template-id]  nested-name-specifier:

[INSERT: ::]
[DELETE: ::opt] type-name ::
[DELETE: ::opt] namespace-name ::
decltype-specifier ::
nested-name-specifier identifier ::
nested-name-specifier templateopt simple-template-id ::
