33. Argument dependent lookup and overloaded functions
Section: 6.5.4 [basic.lookup.argdep [1]] Status: TC1 Submitter: Jason Merrill Date: 15
Jul 1998

If an argument used for lookup is the address of a group of overloaded functions, are
there any associated namespaces or classes? What if it's the address of a function
template?

My inclination is to say no to both.

From Mike Miller:

We discussed this on the reflector a few weeks ago. I'll leave the template case for the
Core III experts, but I'd find it surprising if the overload case weren't handled as the
obvious generalization of the single-function case. For a single function, the
associated namespaces are those of the types used in the parameters and return type; I
would expect that using an overloaded function name would simply be the union of the
namespaces from the members of the overload set. That would be the simplest and most
intuitive, IMHO — is there an argument for doing it differently?

Proposed Resolution (04/99): In 6.5.4 [basic.lookup.argdep [2]] paragraph 2, add
following the last bullet in the list of associated classes and namespaces for various
argument types (not a bullet itself because overload sets and templates do not have a
type):

In addition, if the argument is the name or address of a set of overloaded functions
and/or function templates, its associated classes and namespaces are the union of those
associated with each of the members of the set: the namespace in which the function or
function template is defined and the classes and namespaces associated with its
(non-dependent) parameter types and return type.
